# natural-writing-zh

一个面向中文文本的自然化编辑 Skill。它用于减少模板腔、官话、翻译腔、重复表达和过度包装，同时尽量保留原文中的事实、术语、限定条件与作者语气。

适用于汇报、方案、邮件、PPT 文案、技术说明、个人文章，以及“去 AI 味”“写得自然一点”“说人话”“减少官话”等改写需求。

## 它解决什么问题

- 把空泛表达改成清楚、具体的中文；
- 删除重复解释和助手式聊天残留；
- 根据汇报、商务、技术、邮件或个人文章调整表达；
- 保护数字、日期、主体、责任、范围、例外和专业术语；
- 避免把计划写成事实、把相关写成因果；
- 在信息不足时保持克制，不编造数据、经历、来源或成果。

## 不适合做什么

- 不判断一段文字是否由 AI 生成；
- 不保证降低所谓“AI率”或通过任何检测；
- 不替代事实核查、法律审查、医学审查、财务审查或合规审查；
- 不主动联网、读取凭证、上传文件或发布内容；
- 不根据模糊材料虚构案例、数字、用户反馈或个人经历。

## 安装

### 直接克隆

将仓库克隆到支持 `SKILL.md` 的本地技能目录：

```bash
git clone https://github.com/BibbyJiang0215/natural-writing-zh.git
```

如果你的工具要求固定的技能目录，请把整个仓库复制到对应目录，并确保以下路径存在：

```text
natural-writing-zh/SKILL.md
```

不同工具的技能目录和加载方式可能不同，请以所用工具的说明为准。

### 小红书 Red Skill

Red Skill 平台只接受单个 Markdown 文件时，请上传专门发布的单文件版 `SKILL.md`。单文件版已经内置必要示例、限制和授权说明，不依赖 `agents/`、`references/` 或单独的许可证文件。

不要直接从本仓库多文件版中单独抽出 `SKILL.md` 上传，因为多文件版会按需读取 `references/examples.md`。

## 使用方式

安装后可以直接用自然语言调用，例如：

```text
请用 natural-writing-zh 对下面这段话做标准改写，只输出正文：

[粘贴原文]
```

```text
轻改这封邮件，保留我的语气和段落顺序，不要增加新的承诺：

```

```text
分析这段汇报里最明显的空话，给出“原句—问题—改写”，然后提供完整改写稿：

[粘贴汇报]
```

```text
把这段技术说明写得更容易理解，但必须保留接口名称、状态、时间和异常处理规则：

[粘贴技术说明]
```

## 改写力度

| 模式 | 适用情况 | 处理范围 |
| --- | --- | --- |
| 轻改 | 原文结构和语气基本可用 | 修正语病、冗余和局部生硬表达 |
| 标准改写 | 大多数日常润色需求 | 合并重复、前移重点、调整句序 |
| 深改 | 用户明确要求重写或重构 | 可以重组全文，但仍保护事实和立场 |

用户未指定时，默认使用标准改写。

## 事实保护原则

Skill 会优先保护以下内容：

- 人名、组织、日期、金额、数量、比例和单位；
- 责任主体、执行顺序、承诺、条件、范围和例外；
- 因果关系、比较对象、证据范围、引用和出处；
- 专业术语，以及事实、推测、计划、目标和建议之间的区别。

如果原文存在疑似错误或内部矛盾，Skill 应保留原文并在正文外提示，而不是静默修改。

## 示例

原文：

> 华东仓计划在 10 月 15 日前完成 12 台设备的试运行，目前完成 8 台。项目负责人是陈敏，预算上限为 36 万元。

改写：

> 华东仓计划于 10 月 15 日前完成 12 台设备的试运行，目前已完成 8 台。项目由陈敏负责，预算上限为 36 万元。

日期、数量、负责人、预算上限和“计划”状态均应保持不变。更多案例见 [`references/examples.md`](references/examples.md)。

## 安全与隐私

本仓库只包含 Markdown、YAML 和许可证文本，没有可执行脚本，也不依赖外部 API。Skill 本身不需要密码、令牌、私钥或其他凭证。

待改文本可能包含敏感信息。使用前请确认所用 AI 工具和运行环境符合你的隐私、保密与合规要求。
